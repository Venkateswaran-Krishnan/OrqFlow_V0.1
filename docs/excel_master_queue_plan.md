# Excel Input Loading For Master Queue Creator

## Summary

When the bot is a master bot and config says the queue source is Excel, `master_queue_creator` should read the configured Excel file, validate it against `tbl_input`, and insert rows into `tbl_input` only. DB adapter initialization already belongs to `framework_init`; this plan reuses `state["queue_db"]`.

## Trigger Conditions

Run Excel input loading only when all are true:

- `process_config.settings.masterbot` is `true`
- `process_config.settings.Queue` equals `Excel`, case-insensitive
- `process_config.settings.QueueFileLocation` is present and points to an existing file

If `masterbot` is false, skip this block completely.

## Implementation Changes

- Keep the node thin:
  - `framework/nodes.py::master_queue_creator` continues calling `create_master_queue(state)`.
- Implement the behavior in `framework/runtime/queue_runtime.py::create_master_queue`.
- Reuse the shared Excel utility:
  - Load `<share_root>/common/excel.py`
  - Call `read_excel_dataframe(excel_path)`
- Resolve `QueueFileLocation`:
  - Absolute paths are used directly.
  - Relative paths are resolved from `config_context["project_config_dir"]`.
- Use the already initialized DB adapter:
  - `db = state["queue_db"]`
  - Do not create a new DB connection inside master queue creator.
  - Do not insert into `tbl_queue`.

## Excel Validation Rules

- Excel must include exact mandatory `tbl_input` column headers:
  - `Processor`
  - `Process`
  - `Chargeback_Date`
  - `Case_Json`
  - `Case_ID`
- `ID` is not required because it is auto-generated.
- `Input_Identifier` is generated by runtime, not required from Excel.
- Generate `Input_Identifier` per row as:

```text
<Process>_<Case_ID>
```

- Insert optional columns only when the Excel header exactly matches a `tbl_input` DB column.
- Ignore extra non-DB Excel columns.
- If mandatory columns are missing, raise an exception and stop before inserting any rows.

## Insert Behavior

- Insert into `tbl_input` row by row.
- Commit each row independently.
- Let the DB reject duplicates, especially duplicate `Input_Identifier`.
- If a row fails:
  - Stop execution.
  - Include Excel row number and DB error in the exception.
  - Keep earlier committed rows.
- Do not pre-deduplicate in Python.
- Do not insert into `tbl_queue`; separate queue-table logic will handle that later.

## Error Behavior

- Missing `QueueFileLocation`, missing Excel file, missing mandatory columns, missing `state["queue_db"]`, invalid row data, or DB insert failure should set runtime failure state and prevent moving to `get_transaction`.
- The graph should route to `end` or stop cleanly after failure instead of continuing transaction fetch.

## Test Plan

- `masterbot: false` skips Excel loading.
- `masterbot: true` + `Queue: Excel` reads the Excel file.
- Missing mandatory `Case_ID` fails before inserts.
- Valid rows insert into `tbl_input`.
- `Input_Identifier` is generated as `Process_Case_ID`.
- Optional DB-matching columns are inserted.
- Extra non-DB columns are ignored.
- Duplicate `Input_Identifier` is rejected by DB on that row.
- Earlier rows remain committed after a later row fails.
- No rows are inserted into `tbl_queue`.
